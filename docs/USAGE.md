# 使用与限制

[返回 README](../README.md)

## 使用

- **Workspace 悬停预览**：在左侧项目行停留约 350 毫秒后，显示最多 5 个任务及其监听端口；没有端口的任务仍会显示。无需先打开该项目或创建会话。
- 每个任务默认显示 4 个端口，点击“展开更多”显示全部端口，可再次收起。浮层最高 430px，并受视口高度限制，超出后在浮层内部滚动。
- 0.3.1 悬停预览去掉分组标题、重复项目名和重复运行项。指令显示为一行脚本名与运行/停止图标；点击脚本名可展开实际指令与定义，子项目目录在同一行显示。PID 保留在运行任务的命令悬停提示中。悬停预览只保留任务、端口和可运行脚本，不显示历史运行记录或扫描警告；这些信息在完整面板查看。
- 鼠标可以从项目行移入预览继续阅读；移出或按 Esc 关闭。点击预览内的开始/停止等按钮不会关闭预览。预览按需扫描；浮层中有插件启动的活动任务时，每 3 秒更新状态，关闭或任务结束后停止轮询。
- 面板随当前会话的工作目录切换，默认每 5 秒刷新；隐藏面板或切换浏览器标签页时暂停采集。
- 搜索框支持命令、运行时、PID、目录和端口，多关键词按同时匹配过滤。
- 点击任务展开工作目录、项目归属依据、子进程和完整端点；点击端口复制 `address:port`。
- npm / shell / node 等可识别的启动链会保守地合并展示。独立任务不会因为共用交互式 shell 而合并。
- 默认隐藏语言服务器、IDE 辅助进程、共享 Gradle daemon 等工具进程；勾选 **Include tool processes / 包含工具进程** 可查看。
- **DSH background jobs** 单独显示当前会话仍在运行的已注册任务。由于 DSH 的公开 job 记录没有 PID，它们不会被猜测合并到系统进程中。
- TCP 显示真实 LISTEN socket；UDP 显示未连接的绑定端点。没有端口不代表任务已经结束，监听端口也不代表应用已经就绪。

### 启动项目指令

- **可运行指令 / Available commands** 自动读取当前 Workspace 根目录和子项目的 `package.json` scripts。
- 每条显示脚本名、项目目录、包管理器和脚本定义；点击三角形运行图标启动，支持 npm、pnpm、yarn、bun。
- 包管理器优先取项目的 `packageManager` 字段，其次取本地 lockfile，再继承父项目配置，最终默认 npm。使用 DSH Host 已安装的版本，不会自动下载包管理器或安装项目依赖。
- 启动时重新发现并校验选中的 script。该 script 的定义、包管理器或子项目目录变化后，原指令 ID 会失效，需刷新列表；浏览器不能提交任意 shell 文本或工作目录。
- 同一条脚本运行时再次点击会返回当前运行实例，避免重复启动。最多同时运行 8 条由插件管理的指令。
- 完整面板可以展开由插件启动任务的输出日志，并查看完成、失败及退出码。输出仅在内存保留，单条最多 64KiB，历史记录最多 100 条。面板的手动刷新会同时重读脚本列表。
- 关闭悬停卡片、切换项目、关闭浏览器不会停止已经接受的启动任务。禁用或卸载插件、退出 DSH 时会请求停止由插件管理的活动任务。
- 0.3.0 的指令发现覆盖 `package.json` scripts；Makefile、Maven、Gradle 等任务定义尚未自动列出。扫描不会执行发现的脚本，只有点击运行才执行。

指令扫描跳过 `node_modules`、`.git`、构建产物和虚拟环境目录，并限制到 1000 个目录、8 层深度、300 个 package 与 1000 条脚本；到达上限会给出提示。包管理器按其正常语义执行 scripts，包括相应的生命周期脚本。

### 停止运行任务

- 悬停卡片及完整面板中，任务旁的方形停止图标用于请求终止。操作期间按钮禁用，完成后刷新列表。
- 由插件启动的任务使用其自身进程组停止，先请求正常退出；仍能确认属于该活动任务时，可在短暂等待后强制结束其进程组。
- 对从其他终端或 IDE 启动的外部任务，操作前重新扫描并核对 PID、启动身份、用户、工作目录和进程关系，只对经过校验的成员发送 **SIGTERM**，不自动强制杀死。
- 外部任务若仍在清理资源，会显示停止请求已发送；部分进程未停止时会明确反馈，不能当作全部停止成功。
- 仅凭命令路径推断归属的任务、工具/基础设施进程，以及缺少可验证身份的进程，停止按钮不可用；不会按用户提供的任意 PID 终止系统进程。
- 主动 daemonize、退出启动进程后遗留的后台服务不能凭旧进程组 ID 接管；这些服务由系统扫描作为外部任务发现并按上述规则停止。

## 平台与范围

| 平台 | 实现 | 验证情况 |
| --- | --- | --- |
| Linux / Ubuntu | `/proc` 进程信息、cwd、启动时间与 socket inode 关联，不需要 lsof/ss/Python | Linux 容器内真实 TCP/UDP、无端口 worker，以及 17 项脚本发现/启动/停止测试 |
| macOS | 系统 `ps`、`lsof` | 本机真实 TCP/UDP、脚本启动/停止，以及 17 项外部进程停止测试 |
| Windows | PowerShell CIM、Get-NetTCPConnection、Get-NetUDPEndpoint | 解析与归属 fixture 测试；尚未进行 Windows 实机验证；启动和停止不可用 |

当前 macOS 可直接使用，Linux / Ubuntu 采集也已实测。采集与语言无关，Node.js、Java、Python、Go 或自定义可执行文件都按操作系统进程处理。

采集范围是 DSH Host 所在的进程与网络命名空间、当前系统用户有权读取的进程。Docker 内运行的 DSH 只能看到它所在容器可见的进程；不会自动扫描宿主机、其他容器、WSL 或 SSH 远端。容器端口映射、服务健康检查、外部任务日志接管和跨重启历史持久化不在 0.3.0 的范围内。

工作目录位于项目内是主要归属依据；绝对项目路径出现在命令中、缺少 cwd 时的父子关系作为补充依据。命令路径匹配是推断，详情中会注明。外部进程的原始 shell 文本（alias、变量展开前内容、引号等）无法可靠还原；显示的是仍能观察到的进程命令。短于刷新间隔的任务可能被漏过。

## 数据与访问

- 采集只读；运行和停止仅通过用户主动操作的命令管理接口执行。
- 通过 DSH Connection 的认证通道请求，只有 DSH owner 可以查看和管理 Host 任务。
- 浏览器用会话 ID 或 Workspace ID 定位项目；启动、停止和日志请求另外传入已列出的指令 ID、任务 ID 或运行 ID。Host 从会话 header 或 Workspace 注册表获取工作目录，不接受浏览器传入任意路径或 PID。
- 不读取其他进程的环境变量，不持久化扫描结果，不调用模型、不消耗模型 token，不发送遥测。由插件启动的指令继承 Host 的进程环境。
- 展示前会尽力遮蔽常见 token、password、API key、URL 密码等命令参数。自定义敏感参数仍可能出现在命令行中，请避免把密钥直接写进启动命令。
- 扫描有超时、取消、并发上限和短期缓存，权限不足会在完整面板显示部分信息提示。

## 常见问题

- **不兼容的 DSH 版本**：用 `dsh --version` 查看版本，确认落在 `package.json` 的 `engines.dsh` 范围内。新版本先运行 `npm run check:dsh` 验证，再放宽范围；不要删除版本限制或改回精确版本。原因与步骤见[兼容性](COMPATIBILITY.md)。
- **找不到安装包**：确保 `.tgz` 位于 DSH 所在服务器，并在 UI 输入绝对路径。
- **安装成功但没有入口**：确认插件已启用，按提示刷新/重启；先进入项目的会话，再打开右侧栏的新增标签页入口。
- **列表为空**：确认命令在同一个 Host / 容器、同一个系统用户下运行，cwd 或绝对命令路径与项目一致；可勾选包含工具进程。
- **部分端口缺失**：进程可能退出、尚未监听、处于其他网络命名空间，或操作系统拒绝读取 socket 信息。
- **无法扫描**：确认连接拥有 DSH owner 权限，项目目录仍存在，Linux `/proc` 已挂载且当前用户有读取权限。
